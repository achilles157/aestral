☁️ Panduan Cloudflare API Token

Auto-deploy Worker Aestral via GitHub Actions · Revisi 2026-08-07
🔑 Kenapa panduan ini ada?

Workflow .github/workflows/deploy-worker.yml di repo Aestral butuh 2 GitHub secrets yang belum terpasang:

  • CLOUDFLARE_API_TOKEN — token API Cloudflare (bukan password akun)
  • CLOUDFLARE_ACCOUNT_ID — ID akun Cloudflare

Tanpa keduanya, workflow gagal dengan error: In a non-interactive environment, it's necessary to set a CLOUDFLARE_API_TOKEN environment variable. Token Cloudflare memang punya banyak spesifikasi (permission, scope akun/zone, TTL) — panduan ini memilihkan yang paling minimal dan aman untuk kebutuhan deploy Worker saja.

0. Konsep penting: API Token vs API Key

Cloudflare punya 3 jenis kredensial — sering bikin bingung:

JenisKegunaanUntuk kita?
API Token (recommended)Token khusus per-tugas: bisa dibatasi permission, scope, dan masa berlaku✅ Ini yang kita pakai — aman & presisi
Global API Key"Kunci utama" akun — akses penuh ke semua akun❌ JANGAN — terlalu berbahaya, dan tak bisa di-scope
Origin CA Key / Scoped KeysKasus khusus (SSL origin, dll)❌ Tidak relevan
⚠️ Jangan pernah pakai Global API Key di GitHub Actions

Global API Key = setara password akun. Kalau bocor ke log CI, orang lain bisa menguasai seluruh akun Cloudflare-mu. API Token hanya bisa menghapus/membuat Worker, dan bisa dicabut kapan saja.

1. Ambil Account ID (1 menit)

1

Login ke dash.cloudflare.com.

2

Di halaman mana pun, lihat pojok kanan bawah sidebar → kotak "Account ID" (32 karakter hex, contoh: af72b75133ce4041990a3b04f08ed3e9).

Alternatif: URL dashboard biasanya berbentuk dash.cloudflare.com/<ACCOUNT_ID>/... saat kamu di dalam sebuah domain/worker.

3

Salin ID-nya — ini untuk secret CLOUDFLARE_ACCOUNT_ID. Simpan dulu, kita isi di Langkah 4.

2. Buat API Token (5 menit)

1

Buka My Profile → API Tokens (atau klik ikon orang kanan atas → My Profile → tab API Tokens).

2

Klik tombol Create Token.

3

Scroll ke bagian template, pilih "Create Custom Token" (paling bawah) → klik Get started.

3a. Isi form token — spesifikasi persis

FieldIsiCatatan
Token nameaestral-worker-deployBebas, tapi beri nama jelas
Permissions → AccountWorkers Scripts → EditWAJIB — untuk upload script Worker
Permissions → AccountAccount Settings → ReadDISARANKAN — wrangler membaca info akun saat deploy
Permissions → ZoneZone → ReadOPSIONAL — hanya perlu jika Worker pakai custom domain/route zone; untuk *.workers.dev murni tidak wajib
🎯 Prinsip minimal privilege

Jangan menambah permission lain (mis. Account → All permissions atau Zone → DNS Edit). Token kita hanya boleh: edit Workers Scripts + baca Account Settings. Semakin kecil scope, semakin kecil risiko kalau token bocor.

3b. Account Resources

  • Bagian Account Resources → pilih Include → pilih nama akun Cloudflare-mu (biasanya cuma 1).

3c. Zone Resources

  • Pilih Include → All zones (paling sederhana).
  • Kalau mau lebih ketat dan hanya deploy ke *.workers.dev: pilih Include → Specific zone dan pilih domain yang relevan, atau kosongkan zone sepenuhnya (kalau UI mengizinkan) — karena Worker di workers.dev tidak terikat ke zone tertentu.

3d. Client IP Address Filtering & TTL (opsional tapi disarankan)

FieldSaranKenapa
Client IP Address FilteringKosongkan (semua IP)GitHub Actions memakai banyak IP yang berubah-ubah; membatasi IP malah bikin workflow gagal acak
Time to Live (TTL)Start: now · End: +1 tahun (atau sesuai selera)Token dengan masa berlaku = lapisan keamanan ekstra; kamu akan diingatkan sebelum kedaluwarsa. Bisa dibuat ulang kapan saja
4

Klik Continue to summary → periksa ringkasannya → Create Token.

🔴 PENTING: salin token SEKARANG

Cloudflare menampilkan token hanya sekali di layar (kotak biru "Token: …"). Klik ikon copy lalu simpan di password manager / file sementara. Begitu halaman ditutup, token tidak bisa dilihat lagi — harus buat baru.

3. Verifikasi token dulu di lokal (disarankan, 1 menit)

Sebelum pasang di GitHub, cek token-nya bekerja. Jalankan di terminal (folder mana pun):

# Windows PowerShell — pakai token yang barusan disalin
$env:CLOUDFLARE_API_TOKEN = "TOKEN_YANG_BARU"
npx wrangler whoami

Jika muncul nama email & ID akun kamu → token valid. Jika muncul error permission, ada yang salah di Langkah 3a.

4. Pasang secrets di GitHub (2 menit)

1

Buka repo achilles157/aestral → tab Settings → sidebar kiri Secrets and variables → Actions.

2

Klik New repository secret. Buat dua secret:

Name (PERSIS)Value
CLOUDFLARE_API_TOKENToken dari Langkah 2 (mulai dengan huruf/angka acak panjang, contoh format: abc123DEF456...)
CLOUDFLARE_ACCOUNT_IDAccount ID 32-hex dari Langkah 1

Nama harus persis — workflow memanggil secrets.CLOUDFLARE_API_TOKEN dan secrets.CLOUDFLARE_ACCOUNT_ID.

3

Setelah kedua secret tersimpan, buka tab Actions → pilih workflow Deploy Worker (Cloudflare) → tombol Run workflow → Run workflow (gunakan branch main).

4

Tunggu selesai — harusnya muncul checkmark hijau dan log deploy menampilkan:

Uploaded aestral-backend (3.2 sec)
Current Version ID: ...
Deployed ... workers.dev (2.1 sec)

6. Keamanan & pemeliharaan

  • Rotasi berkala: buat token baru setiap ~6–12 bulan, hapus yang lama di halaman API Tokens.
  • Jangan commit token: token hanya boleh hidup di GitHub Secrets dan file .dev.vars lokal (yang sudah di-.gitignore).
  • Cabut cepat: kalau curiga bocor → halaman API Tokens → Roll (buat ulang) atau Delete seketika.
  • Monitoring: GitHub mengirim email saat secret dipakai; Cloudflare juga mencatat aktivitas API di audit log.
